# Fully native workflow

Every module, stable or not, is cloned into `~/ros2_ws` and run from
source. Nothing runs from an image.

This is not the recommended workflow. Use it when you need to change a
stable module itself, or on a machine that cannot pull images. Otherwise use
the [hybrid workflow](/development/hybrid).

## What you gain and what you take on

You gain complete control. Every line of the stack is in your workspace, you
can read and change any of it, and a debugger reaches all of it.

You take on building and maintaining other labs' code. Each stable module has
its own dependencies, its own build, and its own release cadence, and the
images exist so that you do not have to track them. Your stack also drifts
from what the chair runs: the chair runs pinned images, and a source checkout
is whatever commit you last pulled. A problem that appears only on the chair
is harder to reproduce from here.

## Set it up

Start from the [hybrid workspace](/development/hybrid#set-up-your-workspace),
then add the stable modules to it.

| Module | Get it |
| --- | --- |
| Interfaces | Already in the workspace |
| Arm driver | `git clone https://github.com/rammp-org/kinova-gen3-ros2.git` into `src/`, then `vcs import src < src/kinova-gen3-ros2/kinova_gen3.repos` to bring in the low-level driver it vendors. |
| Planner | The arm's `go_to_*` actions call the cuRobo planner, which is its own module: [RAMMP-CuRobo](https://github.com/rammp-org/RAMMP-CuRobo). Its install is long and GPU-bound; its README covers it. Skip it if you only need trajectory execution and setpoint streaming. |
| Cameras | `sudo apt install ros-humble-orbbec-camera ros-humble-realsense2-camera`. The camera images contain these packages and nothing else. |
| Base driver | Does not exist yet. |

```bash
cd ~/ros2_ws
rosdep install --from-paths src --ignore-src -y
colcon build
source install/setup.bash
```

## Run it

There are two ways to run the stack. Launch each module by hand with
`ros2 launch`, as its own docs describe. Or give each node in the manifest a
`launch_file` alternative on
the `dev` machine, the same shape as the
[`frame_counter → native`](/development/hybrid#let-sheppy-launch-it-optional) entry,
and save a profile that selects them. The second keeps `sheppy status` as
the one place to see what is running.

Develop your own package exactly as in the
[hybrid workflow](/development/hybrid#write-a-package-and-run-it).

## Getting back

To return to the hybrid workflow, `sheppy up real-arm-cameras` selects the
image alternatives again. Remove the stable modules' checkouts from `src/`,
or add a `COLCON_IGNORE` file to each, so your host builds go back to the
pinned interfaces tag rather than whatever those checkouts carry.
