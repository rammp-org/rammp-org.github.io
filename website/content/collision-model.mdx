# Motion planning: collision model

Each robot's [cuRobo planner](https://github.com/rammp-org/RAMMP-CuRobo) plans around a
collision world of boxes and checks the arm against it as a set of spheres. This page draws
both, for every robot in [rammp-deployments](https://github.com/rammp-org/rammp-deployments)
that has a `config/robots/<robot>/curobo/planner.yaml`. The data is read from its `dev`
branch each time this site is built, so it shows what is merged there.

Pick a robot, then a pose: the arm's spheres are placed by forward kinematics of the robot's
`arm_kinematics.json` on its mount, and the clearance table gives each box's distance to the
nearest sphere as the planner measures it. Click a box in the 3D view, the drawing or a table
to read its extents.

<Callout type="warning">
  flatbot's chair, seat and occupant are best guesses, not yet measured on the chair: the Gen1.2
  MEBot geometry, a seat, and a seated adult from a 5th-percentile woman to a 95th-percentile
  man. At its rest pose the arm sits inside the occupant and the backrest, so the planner refuses
  a plan that starts there. Measure the chair with the key-dimensions panel and edit
  `curobo/mebot_layers.yaml`.
</Callout>

## Where the numbers come from

- **The world.** `planner.yaml` names the robot file and the start-up world, and lists the
  layers that are in every world. The world file (`world.yaml`) brings its own boxes and its
  own layers, and must be in `arm_mount`. Names resolve next to the file that lists them. The
  planner pads every box by `world_padding` per side (0.02 m unless `planner.yaml` sets it),
  except the world's own boxes named in `no_pad_names` (the arm's `pedestal`).
- **The chair layers.** flatbot's `layer_mebot_*.yaml` are generated by RAMMP-CuRobo's
  `scripts/generate_layers.py` from `mebot_layers.yaml`, next to them. Never edit the
  layers by hand: edit `mebot_layers.yaml` and run `make layers` from a RAMMP-CuRobo checkout,
  as `planner.yaml` describes. The key-dimensions panel appears for a robot whose layers
  carry the generator's metadata.
- **The arm.** `robot.yaml` gives the spheres (`collision_spheres`, grown by
  `collision_sphere_buffer`) and the IK seed (`retract_config`); `arm_kinematics.json` gives
  the joints below `arm_base_link`; `../mount.yaml` gives the tilt from `arm_mount` to
  `arm_base_link`.
- **The rest pose** is where flatbot's arm parks, read from `/joint_states`. Only flatbot has
  one here.

The data behind each robot is also published as JSON, at
`/collision-models/<deployment>-<robot>.json` on this site.
