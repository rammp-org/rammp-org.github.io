# RAMMP Gen 1.5 hardware

Gen 1.5 is the current RAMMP chair: the hardware every module on this site is
built against. This page covers what is on it: the wheelchair base, the Kinova
arm and its wrist attachment, the compute, and the sensor suite. The software
it runs is on [Software versions & core repos](/software). Setting a Jetson up
to develop against it is [Developer setup](/setup).

The RAMMP base is the [MEBot](https://www.herl.pitt.edu/mebot), the Mobility
Enhancement Robotic Wheelchair created at HERL. It actuates its caster wheels
and drive wheels independently, which lets it climb curbs and level the seat on
uneven terrain. Sensors in the base include joint encoders, load cells, and an
IMU.

RAMMP uses a [Kinova Gen3](https://www.kinovarobotics.com/product/gen3-robots)
7 degree-of-freedom arm for manipulation tasks. The ROS 2 interface to it is
documented under [Controlling the arm](/kinova-gen3-ros2).

## Kinova Wrist Puck Attachment

Kinova developed a custom wrist attachment that exposes I/O routed through the
arm. Its connector pinout and the signals it carries are not documented here
yet.

## Compute

Everything on the chair — the arm driver, the base, perception, and every
module you contribute — runs on one NVIDIA Jetson.

| | |
| --- | --- |
| Module | [NVIDIA Jetson AGX Orin 64GB Developer Kit](https://developer.nvidia.com/embedded/learn/get-started-jetson-agx-orin-devkit) |
| SoC | Tegra234 — 12 Arm Cortex-A78AE cores, Ampere GPU at compute capability `sm_87` |
| Memory | 64 GB, shared between CPU and GPU |
| Storage | WD_BLACK SN7100 1 TB NVMe SSD (`WDS100T4X0E`), M.2 2280, PCIe Gen4, in the dev kit's M.2 Key M slot |

The GPU is why the [`rammp-cuda`](/publishing/base-images#rammp-cuda) base image
exists. The NVMe is there because the dev kit's 64 GB of eMMC is not enough:
`rammp-cuda` alone is several gigabytes, every module is its own image on top
of it, and during an upgrade you hold more than one tag of each.

### Real-time

The Kinova Gen3 low-level driver closes a 1 kHz torque loop over Ethernet. A
missed cycle trips the arm's watchdog and faults the arm. The base actuation
loop has a deadline of its own; its rate is not documented here yet. Both need
bounded wake-up latency, which the stock JetPack kernel does not give, so the
Jetson runs a PREEMPT_RT kernel with one core isolated for the control loop.
The kernel version is on [Software versions](/software#versions). The settings
that make it hold, and how to apply them, are in
[Developer setup](/setup#the-jetson).
